## T2 · 验证码自动复制（需求与判据）

> 状态沿革：2026-10-13 用户先说「就用官方镜像，不用复制了」，随后改为「开发路径给我，我叫豆包去改」→ 现在交豆包实现（T3）。


**需求**：Bark 收到的短信推送，希望能**直接复制验证码**（不用打开 App 手选）。

**上游现状（已查实）**：`copy`/`autoCopy` + 验证码提取存在于 `main` 线，但**生产同源线 `a0e2d642` 明确删除了它**（上游提交 `d0971537`：*remove verification code extraction and auto-copy*）。
⇒ 官方镜像永远不会带这功能，必须自建。

**验收判据（实现完成后由守门人独立复核）**
- A1 源码：`grep -c autoCopy internal/notify/bark.go` ≥ 1，且 `go test ./internal/notify/...` 全绿
- A2 **端到端（唯一算数的判据）**：真实短信进来后，`docker logs vohive` 里 `Bark 推送成功` 的同一刻，Bark 服务端日志 `POST /push` 的 JSON 里出现 `"copy":"<验证码>"` 与 `"autoCopy":"1"`
- A3 **负例**：营销类（无验证码）短信的推送体里**不得**出现 `autoCopy`（避免覆盖剪贴板）
- A4 **造反例**：把开关 `bark.auto_copy` 置 false 后重推同一条 → `copy`/`autoCopy` 字段消失（证明开关不是死开关）
- A5 回滚可用：`deploy.sh` 换 `IMAGE_TAG` 回官方镜像 → 版本串与行为回到现状

## 本项目特有红线
- **串口互斥**：`vohive` 与 `freepbx` 只能有一个在跑（都独占 `/dev/ttyUSB2`）；切换前后都要确认对方已停。
- **不许源码遮蔽**：容器不许挂 `projects/openvohive`（`deploy.sh` 第 ⑥ 步会拦）。
- **不许热改容器**：不 `docker cp` / 不在容器里改文件（改代码只能走 发版→部署）。
- **模块不开数据**：`network_enabled=false`（防抢默认路由）。
- **凭据不入库/不入对话**：Bark `device_key`、Web 密码只放 `.env` 与 `/vol1/1000/Docker/openvohive/data/config.yaml`。

> 用户 2026-10-13 决定：先搁置，后又改主意 —— 「你把开发路径给我，我叫豆包去改」。本单自包含，收件人只靠本仓库即可开工。
> 实现者=豆包（写码/自测/发版/部署受授权操作）；守门人=Hermes（定判据、独立复核、不替写业务码）。

### 你要做什么（一句话）
在本仓库分支 `nas`（基线 `a0e2d642` = 生产镜像构建源）上补回「验证码识别 + Bark `copy`/`autoCopy`」，让验证码自动进剪贴板；**其余行为必须与线上现役镜像完全一致**。

### 背景（已查实，别重复考古）
- 上游把该功能从生产线删了：`d0971537` *refactor: remove verification code extraction and auto-copy*（2026-07-13）
- 带该功能的是另一条更旧的线 `main`（`00d24b58`，bark.go 206 行，含 `extractVerificationCode`）——**只抄它的两个字段与正则思路，不要把整条线的代码搬过来**（会丢掉生产线的「通知 fail-fast / 重试重写 / URC 噪声抑制」修复）
- 生产实测：Bark 服务端收到的 `POST /push` 里**没有** `copy`/`autoCopy`（这是"功能缺失"的证据）

### 改哪些文件（精确到点）
1. `internal/notify/bark.go`
   - `barkPushPayload` 增加两个字段：`Copy string \`json:"copy,omitempty"\``、`AutoCopy string \`json:"autoCopy,omitempty"\``
   - `SendWithContext` 构造 payload 处（约 88–94 行）：**仅当识别到验证码且开关打开**时填 `Copy=<验证码>`、`AutoCopy="1"`；否则两个字段都留空（靠 `omitempty` 消失）
2. `internal/notify/bark_code.go`（新建）
   - `extractSMSContent(text)`：通知文本格式是
     `收到新短信 / 蜂窝\n设备  ec20\n号码  138…\n时间  2026-…\n内容  <正文>`，取「内容 」那一行做正文（**不要**直接在整段文本上抓数字，会抓到时间/号码）
   - `extractVerificationCode(正文)`：正则按优先级 ① `验证码[是为：:]?\s*(\d{4,8})` ② `(?i)code[\s:=]+(\d{4,8})` ③ 独立 4–8 位数字；找不到返回空
3. `internal/config/config.go`
   - `BarkConfig` 增加 `AutoCopy bool \`mapstructure:"auto_copy"\``
   - **必须同时** `viper.SetDefault("bark.auto_copy", false)`：viper 的 `AutomaticEnv` 对**没注册默认值**的键不读 env（`bark.device_key` 就踩过这个坑，env 传了但不生效）。注册后 `PROXY_BARK_AUTO_COPY=true` 才可用。
   - 默认 **false**：我方部署显式打开，别人拿到这版不会被莫名覆盖剪贴板
4. `internal/notify/bark_code_test.go`（新建，**必须**，否则 CI 的双向断言会红）
   - 正例1：`内容  验证码 123456，5分钟内有效` → `copy=123456`、`autoCopy=1`
   - 正例2：`内容  your code: 8899` → `copy=8899`
   - 负例：`内容  【中国银联】用云闪付乘北京地铁…` → **不含** `copy`/`autoCopy`
   - 造反例：开关 false + 含验证码 → **不含** `copy`/`autoCopy`（证明开关真有效，不是死开关）
   - 自包含：只测纯函数与 payload 序列化，不联网、不读生产数据、不依赖宿主路径

### 发版 / 部署
```bash
# 发版：VERSION 已是 0.1.0 → 提交后打 tag（release 工作流会构建+冒烟+推 GHCR）
git push origin nas && git tag -a v0.1.0 -m "feat: Bark 验证码自动复制" && git push origin v0.1.0
# 部署：先拿用户放行（会重启容器 → 短信中断约 1 分钟）
cd /vol1/1000/Docker/openvohive && vi .env     # IMAGE_TAG=v0.1.0
bash /vol1/1000/Docker/dev-workspace/projects/openvohive/deploy/deploy.sh
```
⚠️ 部署前确认 `freepbx` 没在跑（两者都独占 `/dev/ttyUSB2`，deploy.sh 第①步会拦）。
⚠️ 部署目录若还是「手写的 image 指向官方镜像」，按方案 S4 改成 `include` 仓库内 `deploy/docker-compose.yml` 的薄 wrapper。
